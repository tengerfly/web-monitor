# web-monitor 功能清单

> 版本：v0.1（基石版本）
> 定位：企业级前端监控基建 —— 一次部署，后续所有前端项目「改配置即可接入」。
> 设计原则：**性能监控与用户行为追踪物理分离、按需引入**；问题溯源作为独立能力包，依赖两者数据但可单独启用。

---

## 0. 参考来源与取长

| 参考项目 | 定位 | 本项目的取舍 |
|---|---|---|
| `kisslove/web-monitoring` | 前端监控平台（Angular + Node + MongoDB） | 借鉴「多站点管理 + 自定义阈值 + 邮件告警 + Docker 一键部署」的平台形态 |
| `a597873885/webfunny_monitor` | 前端监控 + APM + 埋点三合一 | 借鉴「用户细查、行为回放、SourceMap 源码定位、慢接口 Top、告警规则、集群化」的能力上限 |
| `clouDr-f2e/monitor` | 轻量 SDK（TS + Rollup + pnpm monorepo） | 借鉴「按端按能力分包、hooks 高定制、单测/e2e 覆盖」的 SDK 工程范式 |
| `nightscout/cgm-remote-monitor` | ⚠️ 血糖监测 Web 应用，非前端监控 | 仅借鉴「插件体系 + 环境变量开关」思路，其余不采用 |

**本项目差异化的点**：
1. **性能 / 行为 硬分离**：`@web-monitor/performance` 与 `@web-monitor/behavior` 可各自独立安装、独立启用，互不牵连，体积按需付费。
2. **溯源优先**：错误发生时的「行为轨迹快照（breadcrumbs）+ 接口调用链 + 会话回放」三件套默认打通，用 `traceId / sessionId` 串联。
3. **统一协议**：全端（Web / 框架 / 未来小程序）共用一套上报协议与一份服务端，接入成本恒定。
4. **多租户 + 应用级配置**：每个接入方一个 `appKey`，采样率、开关、阈值、脱敏规则在线下发，前端无需发版即可调节。

```

│                └─ 框架适配：react / vue                                            │
```

## 11. 接入方式速览（按需组合）

```bash
# 只监控性能
pnpm add @web-monitor/core @web-monitor/performance

# 只追踪用户行为
pnpm add @web-monitor/core @web-monitor/behavior

# 性能 + 错误溯源（含行为轨迹）
pnpm add @web-monitor/core @web-monitor/performance @web-monitor/error

# 全量（性能 + 行为 + 溯源 + 回放）
pnpm add @web-monitor/core @web-monitor/performance @web-monitor/error @web-monitor/behavior @web-monitor/replay
```

```ts
import { createMonitor } from '@web-monitor/core';
import { performancePlugin } from '@web-monitor/performance';
import { errorPlugin } from '@web-monitor/error';

createMonitor({
  appKey: 'wm_xxxxxxxx',
  host: 'https://monitor.example.com',
  plugins: [
    performancePlugin({ /* 性能独有配置 */ }),
    errorPlugin({ /* 溯源独有配置 */ }),
  ],
}).start();
```

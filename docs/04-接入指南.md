# web-monitor 接入指南

## 1. 选择要安装的包

| 场景 | 安装 | 说明 |
|---|---|---|
| 只看性能 | `@web-monitor/core` `@web-monitor/performance` | 适合 CDN、静态站、营销页 |
| 只看行为埋点 | `@web-monitor/core` `@web-monitor/behavior` | 业务分析团队独立使用 |
| 性能 + 错误溯源 | `@web-monitor/core` `@web-monitor/performance` `@web-monitor/error` | 技术团队最常见的组合 |
| 全量 | 上述 + `@web-monitor/behavior` `@web-monitor/replay` | 完整能力 |
| React / Vue | 追加 `@web-monitor/react` / `@web-monitor/vue` | 框架适配 |

> `@web-monitor/core` 是唯一的必装包，它承担会话、上下文、上报管道与插件体系，其余能力包均为可选插件。

## 2. 初始化

```ts
import { createMonitor } from '@web-monitor/core';

const monitor = createMonitor({
  appKey: 'wm_xxxxxxxx',        // 在「应用管理」创建应用后获得
  host: 'https://monitor.example.com',
  env: 'production',            // production / staging / development
  appName: 'shop-web',
  appVersion: '1.4.2',          // 用于版本对比与 SourceMap 定位，务必与构建版本一致
  sampleRate: 1,
  plugins: [],                  // 见下文
});

monitor.start();
```

### 常用配置项

| 配置 | 默认 | 说明 |
|---|---|---|
| `appKey` | — | 必填，应用唯一标识 |
| `host` | — | 上报服务地址 |
| `sampleRate` | 1 | 全局采样率，0-1 |
| `batchSize` | 10 | 达到条数立即上报 |
| `flushInterval` | 5000 | 定时上报间隔（ms） |
| `maxLocalQueueSize` | 200 | 本地补报队列上限 |
| `reportOnUnload` | true | 页面隐藏/卸载时强制上报 |
| `interceptRequest` | true | 自动拦截 fetch / XHR |
| `interceptRoute` | true | 自动监听路由变化 |
| `maskRules` | 内置 | 脱敏规则（选择器 / 属性 / 字段） |
| `debug` | false | 输出 SDK 内部日志 |

### 生命周期

```ts
monitor.start();                 // 启动
monitor.stop();                  // 暂停（保留实例与配置）
monitor.flush();                 // 立即冲刷缓冲区
monitor.destroy();               // 销毁并释放所有监听
monitor.isStarted();
monitor.getGlobalMonitor();      // 获取全局实例（setGlobalMonitor 可设置）
```

## 3. 四个能力包

### 3.1 性能监控

```ts
import { performancePlugin } from '@web-monitor/performance';

performancePlugin({
  sampleRate: 1,
  slowApiThreshold: 1000,        // 慢接口阈值（ms）
  slowResourceThreshold: 500,    // 慢资源阈值（ms）
  longTask: true,
  fps: true,
  memory: true,
  whiteScreen: true,
  thresholds: { LCP: 2500, INP: 200, CLS: 0.1, FCP: 1800, TTFB: 800 },
});
```

运行时读取与手动上报：

```ts
monitor.performance.getVitals();                       // 当前已知的 Vitals 快照
monitor.performance.getScore();                        // 0-100 性能评分
monitor.reportMetric('bundle_load', 320, { unit: 'ms' });
```

### 3.2 用户行为追踪

```ts
import { behaviorPlugin } from '@web-monitor/behavior';

behaviorPlugin({
  pv: true,
  route: true,
  click: true,
  clickTargets: [],                        // 留空=全量；填选择器=仅采集命中元素
  clickRoot: undefined,                    // 限定采集范围容器
  exposure: true,
  exposureTargets: ['[data-track]', '.banner'],
  exposureRatio: 0.5,
  scroll: true,
  form: true,
  formValue: false,                        // 默认不上报输入值
  console: false,
});
```

```ts
monitor.track('order_submit', { orderId: 'A2026', amount: 199 });
monitor.behavior.getCurrentPage();
monitor.behavior.getMaxScrollDepth();
monitor.behavior.addBreadcrumb('进入结算流程');   // 会进入错误溯源的轨迹
```

### 3.3 错误与问题溯源

```ts
import { errorPlugin } from '@web-monitor/error';

errorPlugin({
  sampleRate: 1,                    // 错误建议 100% 上报
  minLevel: 'warning',
  maxBreadcrumbs: 30,               // 溯源核心：错误前记录多少条操作
  snapshot: true,                   // 现场快照（内存/网络/最近请求）
  resourceError: true,
  requestError: true,
  consoleError: false,
  businessCodeExtractor: (data) => data?.code,   // HTTP 200 但 code !== 0 也算失败
  ignoreErrors: [/ResizeObserver loop/, 'Script error'],
});
```

```ts
monitor.error.captureException(new Error('业务校验失败'), { orderId: 'A2026' });
monitor.error.captureMessage('库存不足', 'warning', { sku: 'X100' });
monitor.error.captureFatal(error);      // 跳过采样，强制上报
```

**溯源三件套**（每个错误事件都会自动携带）：

| 字段 | 内容 |
|---|---|
| `fingerprint` | 错误指纹，用于跨用户/跨时间聚合归组 |
| `breadcrumbs[]` | 错误发生前的点击、路由、请求、输入、console 序列 |
| `snapshot` | 内存、网络、可见性、当前路由、最近一次请求与成功请求 |

### 3.4 会话回放

```ts
import { replayPlugin } from '@web-monitor/replay';

replayPlugin({
  sampleRate: 0.05,          // 回放体积大，生产环境务必降采样
  flushInterval: 10000,
  maskAllInputs: true,       // 默认遮罩全部输入框
  maskSelectors: ['.user-phone'],
  blockSelectors: ['.ad-banner'],
  recordMouseMove: false,    // 关闭可显著降低体积
});
```

隐私控制标记：

| 标记 | 效果 |
|---|---|
| `<input type="password">` | 自动遮罩 |
| `data-wm-mask` 或 `.wm-mask` | 该元素内文本与表单值全部遮罩 |
| `data-wm-ignore` 或 `.wm-ignore` | 该元素内容不采集（占位显示） |

## 4. 框架接入

### React

```tsx
import { MonitorProvider, MonitorErrorBoundary, useTrack, usePageView } from '@web-monitor/react';

export function Root() {
  return (
    <MonitorProvider options={{ appKey, host, plugins: [...] }}>
      <MonitorErrorBoundary
        fallback={(error, reset) => (
          <div>
            页面异常：{error.message}
            <button onClick={reset}>重试</button>
          </div>
        )}
      >
        <App />
      </MonitorErrorBoundary>
    </MonitorProvider>
  );
}

// 路由埋点（React Router 示例）
function Layout() {
  const location = useLocation();
  usePageView(location.pathname, location.search);
  return <Outlet />;
}
```

### Vue 3

```ts
import { createWebMonitorPlugin, installRouterTracking } from '@web-monitor/vue';

const monitor = createWebMonitorPlugin({
  appKey,
  host,
  captureVueError: true,     // 接管 app.config.errorHandler（保留业务原有处理器）
  captureVueWarn: false,
  plugins: [performancePlugin(), errorPlugin(), behaviorPlugin()],
});

app.use(monitor);
installRouterTracking(router, monitor.instance);

// 组合式 API
const track = useTrack();
track('pay_click', { channel: 'wechat' });
```

## 5. SourceMap 上传

错误堆栈默认指向压缩后的位置。要让错误定位到源码行，需要上传对应版本的 `.map` 文件。

```bash
# 方式一：看板「应用管理 → 接入代码 → SourceMap 管理」上传

# 方式二：调用接口（适合 CI 自动上传）
curl -X POST https://monitor.example.com/api/v1/projects/wm_xxxxxxxx/sourcemaps \
  -H 'Content-Type: application/json' \
  -d '{"appVersion":"1.4.2","fileName":"app.1a2b3c4d.js","content":"<map 文件内容>"}'
```

> 关键点：`fileName` 必须与构建产物文件名一致（**不带 `.map` 后缀**）。服务端会用错误堆栈中的文件 basename 自动匹配。

## 6. 服务端远程配置

SDK 启动后会异步拉取 `GET /api/v1/config?appKey=xxx`，服务端返回的配置会覆盖本地配置：

```jsonc
{
  "sampleRate": 0.5,
  "plugins": { "performance": true, "behavior": false, "error": true, "replay": false },
  "performance": { "slowApiThreshold": 2000 },
  "error": { "maxBreadcrumbs": 50 },
  "maskRules": { "fields": ["idCard"] }
}
```

这让线上治理变得可能：**出问题时先降采样保业务，而不是先下线监控**。

配置在「应用管理 → 编辑」中维护，保存后 60 秒内生效（服务端对 appKey 有 60s 缓存）。

## 7. 常见问题

**Q：为什么错误堆栈只显示 `Script error.`？**
A：跨域脚本默认拿不到错误详情。请在 `script` 标签上加 `crossorigin` 属性，并确保 CDN 返回 `Access-Control-Allow-Origin`。

**Q：监控会不会拖慢业务？**
A：SDK 所有采集逻辑都做了异常隔离，上报走异步批量（默认 5s 或满 10 条），单次请求受 64KB 上限保护，页面卸载时改用 `sendBeacon`。首屏期间不做任何同步阻塞操作。

**Q：数据量太大怎么办？**
A：三层控流：全局 `sampleRate` → 能力包 `sampleRate` → 单事件 `sampleRate`。建议错误数据 100% 上报，行为与回放按 10%~30% 采样。

**Q：如何只采集某些元素的点击？**
A：配置 `clickTargets: ['[data-track]', '.btn-primary']`，只有命中这些选择器的点击才会被采集。

**Q：用户的敏感信息如何保护？**
A：三层防护——① 默认遮罩密码类字段与常见敏感字段名；② 支持 `data-wm-mask` / `data-wm-ignore` 显式标记；③ 服务端上报网关做二次脱敏兜底。

**Q：能同时接入多个应用吗？**
A：可以。每次 `createMonitor()` 会产生独立实例，互不干扰；多个实例的上报走同一个服务端，通过 `appKey` 隔离。

**Q：看板能查到多久以前的数据？**
A：ClickHouse 默认 TTL：事件明细 90 天、错误明细 90 天、回放分片 30 天。可在 `clickhouse-schema.sql` 中按需调整。

# 模块技术方案 — 01 Realtime 页面模块（实时大屏视图）

> 所属：FTDD V1 总纲　|　状态：`[待评审]`

## 1. 模块概述与边界
见总纲 §7（应做/不应做）。核心价值：把 TDD 的 SSE 快照流转为「异常才出声」的大屏视图，状态机覆盖 PRD 全部异常态。

## 2. 上下游依赖
| 方向 | 对象 | 产物/前提 |
|---|---|---|
| 上游 | TDD RealtimeModule | SSE `snapshot` 帧（首帧立即/5s 周期/15s 心跳/retry 帧）、REST 快照、`RealtimeScreenSnapshot` 类型（@web-monitor/types） |
| 上游 | 设计稿 design-system §7 | 34 条 token |
| 下游 | 存量错误详情/告警管理/接入指引 | 新开视图跳转出口 |

## 3. 页面与组件拆分
页面容器 RealtimeScreen 编排 9 个展示组件（总纲 §5），容器/展示分离：展示组件只接 props+回调，取数与状态机全部在 `useRealtimeStream`。

## 4. hooks 数据流
```
useRealtimeStream(appKey)
 ├─ state: { phase: 'connecting'|'live'|'interrupted'|'idle',
 │           everSucceeded: boolean,                // 区分首次失败(AC-013)与更新失败(AC-007)
 │           snapshot?: RealtimeScreenSnapshot,
 │           lastSuccessAt?: string,
 │           failedCategories?: string[] }
 ├─ 主路径: new EventSource(`/api/v1/realtime/screen/${appKey}/stream`)
 │    onmessage(snapshot) → set snapshot + everSucceeded=true + phase='live'
 │    onerror → es.close()；everSucceeded ? phase='interrupted'（保留旧数据+横幅）: 启动 REST 兜底轮询
 │    EventSource retry 帧由服务端控制；切换 appKey → close() 重建（AC-010 快速切换=只受理最后选择）
 └─ 兜底路径(D3): axios `/snapshot` 每 pushIntervalMs 轮询；成功且服务端恢复→重建 SSE
usePrevFingerprints(snapshot.errors): Set<string>   // 与上一轮比对得「新」高亮（A12：一轮消退）
```
渲染分支：phase/interrupted 期间保留旧快照渲染（不清屏，PRD 底线）；`snapshot.failure.status='partial'` → 失败区块就地置空+标注；`'failed'` → StatusBanners(failed) + lastSuccessAt；首次连接且 everSucceeded=false 且超首帧等待 → StatusBanners(firstfail，无时点)。

## 6. 状态管理
页面本地（hook 内 useState/useReducer + refs 持有 EventSource/定时器）；**不改全局 zustand store**（PRD：大屏默认第一个应用、不记忆，与全局 appKey 解耦）；应用选项列表用 @tanstack/react-query 拉取存量 `/projects`（缓存 5 分钟）。

## 7. 关键技术点
1. **EventSource 生命周期**：appKey 变更/组件卸载必须 `close()`（泄漏=连接计数虚高触发服务端背压）；StrictMode 双挂载用 ref 防重复建连。
2. **首帧等待**：`connecting` 超 5s（=pushIntervalMs，须大于服务端最坏首帧时间=类目超时 3s+网络余量）且 everSucceeded=false → 判定首次失败（与 REST 兜底并行，先到先用）。
3. **部分失败渲染**：`failure.categories` 含 'vitals' 等 → 对应区块置空+「本轮更新失败已置空」标注；其余区块正常（不用旧值冒充，与 M01 AC-M01-011 对齐）。
4. **ECharts 深色**：初始化传 token 色（gridline #1E2A45、primary/danger 曲线、tooltip 深底），`prefers-reduced-motion` 时 `animation:false`。
5. **懒加载**：路由级 `React.lazy(() => import('@/features/realtime/RealtimeScreen'))`。

## 8. 实现细节与决策
跳转出口全部「新开视图」（`window.open` 语义由 `<a target="_blank" rel="noopener">` 承担：错误行整行链接 → `/errors/:fingerprint`？——**存量错误详情路由为 `/errors/:id`（fingerprint 语义，以存量 ErrorsQueryModule 的 fingerprint 定位为准）**；告警条目 → `/alerts`（存量告警页）；接入指引 → `/connect`。Esc/浏览器返回不受影响（新开视图）。

## 9. 异常与边界（10 大 UI 状态核对）
加载中（connecting + 加载标识）/空（无数据零值态、错误流空态文案与异常态文案严格区分）/成功（live）/失败（interrupted 横幅+旧数据）/部分失败（就地标注）/断网（REST 兜底轮询）/应用被删（404 → warning 横幅+切换引导）/无应用（引导页）/无数据（零值）/快速切换（只受理最后选择，previous EventSource 立即 close）。重复与取消：切换应用时 abort 旧兜底轮询。失败恢复：全自动（SSE 重连或兜底轮询成功即回 live），无人工刷新依赖。

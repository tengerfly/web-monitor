## 3. 问题清单

### P0（1 条）
| 编号 | 出处 | 问题 | 成因 | 修复判据 |
|---|---|---|---|---|
| CR-B-01 | `common/http.ts` ResponseInterceptor × `realtime.module.ts` stream | 全局 ResponseInterceptor 对 SSE 帧再包装：每帧 `{type:'snapshot', data}` 无 `code` 键 → 走包装分支 → `{code:0,message,data:{type,data}}`，顶层 `type` 丢失 → 客户端 `addEventListener('snapshot')` 永不触发、负载双层包裹。**TDD 明确要求 SSE 绕过包裹器，实现未落实** | @Sse 路由同样会被全局拦截器包裹；「原生 @Sse 天然绕过」的假设错误 | 事件帧类型可被客户端接收（帧含 `event: snapshot` 且 data 为裸快照），以集成断言或手工 curl 验证 |

**建议补丁（P0）**：`common/http.ts` 增加 SSE 元数据跳过 + realtime 控制器打标：
```ts
// http.ts
import { SetMetadata } from '@nestjs/common';
export const SSE_RESPONSE_KEY = 'sse-response';
export const SseResponse = () => SetMetadata(SSE_RESPONSE_KEY, true);
// intercept() 首行：
const isSse = this.reflector?.getAllAndOverride<boolean>(SSE_RESPONSE_KEY, [context.getHandler(), context.getClass()]);
if (isSse) return next.handle() as Observable<ApiResponse<T>>;
// 类需注入 Reflector：constructor(private readonly reflector: Reflector) {}
// realtime.module.ts stream()：加 @SseResponse() 装饰器并在模块 providers 提供 Reflector（全局 APP_INTERCEPTOR 场景 Reflector 可注入）
```

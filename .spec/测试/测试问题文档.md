# 测试问题文档 — web-monitor 实时大屏（⑭ 本轮实测）

> 分级口径：P0 阻断上线 / P1 关键功能或语义缺陷 / P2 次要。每条含复现步骤与证据。

## 发现问题

### TF-01（P1 → 已修复）错误流「新」徽标逻辑反转 + 首帧全量标新
- **复现**：打开 /realtime（mock 推流），首轮渲染后所有错误条目全部显示「新」徽标；此后每帧所有存量条目持续带「新」。
- **期望**（PRD A12）：「新」= 与上一轮比对新出现的条目，高亮一轮；首帧无上一轮，不标新。
- **实际**：`newFingerprints.has(fp)` 判断写反（对「上一轮集合」做 has，把旧条目标成新增），且首帧基线未建立导致全量标新。
- **证据**：screenshots/e2e-lower-sections.png（5 条全部带「新」）。
- **修复**：usePrevFingerprints 返回 {prev, initialized}；容器计算 `当前 − 上一轮` 差集；首帧仅建基线。回归：realtime.test TC-M02-012b（有新增→有徽标；无新增→无徽标）+ 实测徽标数=0（无新增轮次）。
- **归属**：Frontend-Dev（⑫ 开发期未捕获，⑭ 实测发现——测试流程有效性的正向例证）。

### TF-02（P2 → 工具局限，非产品缺陷）mock 服务端两应用返回相同指标
- 复现：切换到企业官网，指标卡数值与演示商城相同。
- 结论：mock-realtime-server.mjs 为联调工具，单数据集；不影响产品逻辑。可在 mock 中按 appKey 区分数据（留后续按需）。

### TF-03（P2 → 注记）告警「触发于」时间时区混用
- mock 数据为 UTC ISO，浏览器本地换算展示与统计时点（服务端本地切片）口径不一致；真实后端联调时确认 ISO 格式后统一（⑬-前 CR-F-01 已注记）。
